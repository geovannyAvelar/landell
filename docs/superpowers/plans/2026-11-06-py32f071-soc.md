# SoC abstraction and PY32F071 core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Run the F4HWN Fusion v5.4.0 image (UV-K5 V3 / K1, PY32F071) in landell, selectable next to DP32G030, up to its first LCD frame.

**Architecture:** A `dp32g030_soc_t` descriptor inside the existing `dp32g030_cpu_t` carries the memory map, VTOR support, region lookup and LCD tap wiring. PY32F071 peripherals start as register files and gain behavior only when running the real firmware shows it is needed.

**Tech Stack:** C11 core, meson, Python/pytest via ctypes (`tests/dp32g030.py`), existing CLI and `landell-gui`.

**Spec:** `docs/superpowers/specs/2026-11-06-py32f071-soc-design.md`

## Global Constraints

- DP32G030 behavior and every existing test body stay unchanged; only the ctypes `Cpu` mirror in `tests/dp32g030.py` may change for the new layout.
- Public names keep the `dp32g030_` prefix.
- PY32F071: flash 128 KB at `0x08000000`, aliased at `0x0`; SRAM 16 KB at `0x20000000`; app image loaded at `0x08002800` (`image_base`); `has_vtor` true. DP32G030: flash 64 KB at `0`, SRAM 16 KB at `0x20000000`, no VTOR.
- PY32 bases/IRQs come from `Drivers/CMSIS/Device/PY32F071/Include/py32f071xB.h` of the pinned firmware (copied into a table, not guessed). GPIO ports A,B,C,F at `0x50000000 + 0x400*n` (F at `0x50001400`); SPI1 `0x40013000`; USART1 `0x40013800`; I2C1 `0x40005400`; ADC1 `0x40012400`; RCC `0x40021000`; FLASH regs `0x40022000`; PWR `0x40007000`; SYSCFG `0x40010000`; DMA1 `0x40020000`; CRC `0x40023000`; TIM1 `0x40012C00`.
- LCD tap on PY32: SPI1, A0 = PA6. On DP32G030: SPI0, A0 = GPIOB pin 9 (unchanged).
- Auto-detect: reset vector (second image word) in `0x08000000..0x0801FFFF` -> py32f071, else dp32g030. `--soc auto|dp32g030|py32f071`.
- Only raw app images are supported.

## Review Focus

- Image larger than the SoC flash (or loaded past its end) is rejected with a clear error, no overflow. Pinned in Task 1.
- Exception vectors honor VTOR on PY32 but a DP32G030 write to VTOR is ignored and reads 0. Pinned in Task 2.
- Unmapped PY32 addresses fault like unmapped DP32G030 ones (no silent success). Pinned in Task 2.
- `--soc py32f071` with a DP32G030 image (reset vector `0x...` low) fails cleanly instead of running garbage. Pinned in Task 6.
- GPIO BSRR set and reset in the same write: reset-low wins on the reset half only as hardware does (set bits `0..15`, reset bits `16..31`; reset wins for a pin in both). Pinned in Task 3.

### Task 3: PY32 GPIO

**Interfaces:**
- Produces: GPIO registers `MODER 0x00`, `OTYPER 0x04`, `OSPEEDR 0x08`, `PUPDR 0x0C`, `IDR 0x10`, `ODR 0x14`, `BSRR 0x18`, `LCKR 0x1C`, `AFR[0..1] 0x20/0x24`, `BRR 0x28` (verify offsets against `GPIO_TypeDef` in the header); effective input pin = driven value if `dp32g030_gpio_set_input`-style host drive, else pull-up/down from `PUPDR`, else 0; output pins (MODER == 01) read back `ODR`. ### Task 4: PY32 SPI1 and the LCD tap

**Files:** Create `src/DP32G030/py32_spi.c`; modify `lcd.c`/`periph.c` (tap decided by `soc->lcd` instead of hardcoded SPI0/GPIOB9), `py32f071.c`, `tests/test_py32.py`.

**Interfaces:**
- Consumes: Task 3 GPIO (`dp32g030_gpio_pins` for A0).
- Produces: SPI regs per `SPI_TypeDef` in the header (`CR1`, `CR2`, `SR`, `DR`, ...): master transfer completes instantly, `SR` TXE/RXNE set, `DR` write calls `hooks.spi_xfer(user, spi, tx)` (rx = returned byte) and, for the LCD SPI, `dp32g030_lcd_spi_byte(c, tx, a0)` where `a0` is the level of the SoC's A0 pin; `soc->lcd = { .spi = 1, .a0_port = 0 (A), .a0_pin = 6 }` for PY32, `{ 0, GPIOB, 9 }` for DP32G030.
